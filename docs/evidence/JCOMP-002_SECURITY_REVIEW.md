## Trust boundary and independent review

TM-008 and TM-020 require bounded original-source recognition and no Groovy
evaluation. The worker checks bytes and text, performs PARSING, recognizes the
restricted source, and invokes CONVERSION only for recognized forms. It checks
actual AST values against those independently recognized in Clojure. Rust
implements a separate bounded parser and independently compares the entire
lowering; worker-supplied hashes alone cannot admit substituted behavior.

Source and context are opened into private bounded regular-file snapshots.
The launcher uses a private copied admission executable and hashes that same
copy. It verifies a caller-pinned immutable image and profile, launches by image
ID with the existing rootless limits, and withholds both response and trusted
receipt until independent validation passes. The only source mount is read-only.
Worker stdout/stderr sentinels, deadline and cleanup remain mandatory. Trusted
implementation digests are observed outside the worker, not trusted as echoes.

Supported, unsupported and rejected outcomes require exact independent agreement;
unknown or disagreeing grammar, internal/profile errors, capacity failures and
timeouts cannot become unsupported coverage. New public validation errors retain
stable codes but use fixed messages, preventing arbitrary worker field values
from being reflected into diagnostic logs. Legacy error behavior is unchanged.

Review resolved lexical diagnostic alignment, stage-count precedence for the
locked N10 fixture, stage argument/name precedence, worker namespace startup
silence, and error-message reflection. The stage-count preflight is generic over
bounded tokens at the stages-block depth; it admits no missing separators and
uses no fixture ID or source hash. Root and a separate Clojure author reviewed
Rust admission and launcher/CLI/harness source; no blocking findings remained
at the focused-check handoff. Final exact-head review is still required.
